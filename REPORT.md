# Звіт: Telegram-колектор публічних каналів

**Джерело:** Telegram (публічні канали через MTProto API / Telethon)  
**Зібрано:** 250 записів у канонічному форматі (sample_data/)  
**Канали:** ukrainska_pravda_fast, ukr_pravda_life, ukrinform_ua, suspilne_news, radiosvoboda

---

## Які ліміти зустріли і як обходили

### 1. FloodWait (головний урок лекції)

**Проблема.** Telegram повертає `FloodWaitError(seconds=N)` коли клієнт робить забагато запитів. Лектор наголосив: бан настає не за *частоту*, а за *обсяг* resolve-викликів `get_entity()`. У продакшн-флоті це призвело до ~24-годинних банів акаунтів після додавання 100+ нових каналів за день.

**Рішення:**
- **Entity cache** у SQLite: кожен `username → (peer_id, access_hash)` зберігається після першого resolve. Повторний запуск — cache-hit, нульовий мережевий виклик.
- **Денний бюджет** `RESOLVE_BUDGET_PER_DAY=60`: лічильник збільшується *до* запиту. Якщо бюджет вичерпано — ціль м'яко відкладається (без помилки, без бану).
- **FloodWaitError handler**: при отриманні виключення → `asyncio.sleep(seconds + 5)` → продовжуємо; зібрані до цього записи не втрачаються.

### 2. Пейсинг (politeness)

Між повідомленнями в batch — `MESSAGE_DELAY=0.05` с з ±10% jitter.  
Між каналами — `CHANNEL_DELAY=2.0` с.  
Результат: колектор виглядає як звичайний клієнт, а не скрипт.

### 3. Дублікати та пропуски

**Проблема.** Якщо скрипт впав посередині batch — частина записів вже в БД, частина ні. При перезапуску без курсора зберегли б дублікати.

**Рішення:**
- `UNIQUE(url)` + `INSERT OR IGNORE` → навіть якщо insert повторюється, БД не ламається.
- Курсор (`last_message_id`) оновлюється *лише після* успішного запису всього batch. При падінні — наступний запуск перезабере batch з того ж місця.

### 4. Стійкість до збоїв каналу

Кожен канал обернутий у `try/except`. Якщо один канал приватний, видалений або дав мережеву помилку — вона логується у `run_log`, прогін продовжується для решти каналів.

## Що зберегли

Повідомлення у єдиній канонічній таблиці `messages`:

| Поле       | Опис                              |
|------------|-----------------------------------|
| author     | @username або channel:<source>    |
| url        | Унікальний permalink (dedup-ключ) |
| date       | ISO-8601 UTC                      |
| text       | Текст повідомлення                |
| media_type | photo / video / document / NULL   |
| source     | Username каналу                   |

Формат сумісний з канонічною моделлю лекції (`author · url · date · text`).  
Дані доступні у `sample_data/messages.jsonl` та `sample_data/messages.csv`.
